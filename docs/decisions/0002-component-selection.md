# ADR 0002: Роли базовых компонентов Personal Expert AI

- Статус: предварительно принято; подлежит пересмотру после прототипов P0–P5
- Дата: 2026-11-01

## Контекст

Платформа должна обеспечивать локальную загрузку и анализ проектной документации, ответы с доказательными ссылками, постоянную память и специализированные инженерные проверки. Рассмотрены AnythingLLM, LM Studio, Hermes Agent, Project Expert AI и Bionic.

Полный анализ находится в `docs/research/ARCHITECTURE_RESEARCH_2026-11-01.md`.

## Решение

1. **Собственный backend — обязательный.** Python/FastAPI управляет пользователями, проектами, документами, задачами, памятью, доступом и вызовами инструментов. Ни один внешний UI или агент не становится владельцем доменной модели.
2. **LM Studio — первый локальный inference runtime.** Доступ к нему выполняется только через LLM provider adapter. Конкретные модели и embeddings выбираются по benchmark.
3. **AnythingLLM Docker — кандидат на UI-прототип.** Проверить API, workspace ACL, citations, document lifecycle, удаление и локальность. Не считать его системным источником истины и не публиковать его API key клиенту.
4. **Hermes Agent — архитектурный референс.** Заимствовать паттерны persistent memory, session search, Skills on-demand и делегирования. Memory Engine и Skills Registry реализовать в доменной модели Personal Expert AI.
5. **Bionic — исследовательская среда.** Использовать для оценки UX агентной работы с файлами и документами. Не использовать как production backend до подтверждения пригодного серверного API и tenant isolation.
6. **Project Expert AI — источник инженерного ядра.** Переносить модули через стабильные контракты и regression tests, не переписывать проверенную логику без необходимости.
7. **PostgreSQL — источник истины.** Векторное и графовое хранилища не фиксировать до сравнительного прототипа.
8. **Изоляция с первого дня.** Все пользовательские сущности, документы, фрагменты, индексы, память и фоновые задачи имеют tenant/project scope.
9. **Local-only — явный режим безопасности.** Облачные провайдеры, внешние MCP, web search и удалённые модели выключены по умолчанию. Сетевую локальность подтверждать инструментальными тестами, а не только настройками интерфейса.

## Рассмотренные альтернативы

- Полностью строить платформу на AnythingLLM: отклонено как основная архитектура, поскольку ingestion/RAG и workspace не заменяют инженерные контракты, provenance и нашу модель данных.
- Встроить Hermes Agent целиком: отложено из-за риска второго центра состояния, памяти, инструментов и управления доступами.
- Использовать Bionic как основу пользовательского сервиса: отложено; исследованные материалы описывают desktop Projects/Sessions и работу с файлами, но не подтверждают готовый multi-tenant server API.
- Сразу выбрать Qdrant или графовую БД: отложено до измерений на репрезентативных проектных комплектах.

## Последствия

- UI и inference runtime можно заменять независимо от инженерного ядра.
- Нужно реализовать собственные API, адаптеры и тесты интеграции.
- Требуются прототипы P0–P5, перечисленные в ROADMAP.
- До завершения P1 нельзя утверждать, что AnythingLLM подходит для конечного UI.
- До завершения P2/P4 нельзя утверждать, что качество документного ingestion и инженерной проверки сохранено при переносе.
- До завершения P5 нельзя считать многопользовательскую изоляцию доказанной.
