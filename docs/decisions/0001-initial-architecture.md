# ADR 0001: Начальные архитектурные принципы

- Статус: принято как предварительное направление
- Дата: 2026-11-01

## Контекст

Нужно создать локальную AI-платформу для загрузки проектной документации, последующего диалога по ней и специализированных инженерных проверок. На первом этапе предполагается один пользователь; архитектура должна не блокировать переход к нескольким пользователям.

## Решение

1. Сохранять собственный Python backend и экспертное ядро независимо от UI.
2. Использовать LM Studio как первоначальный локальный runtime LLM.
3. Рассматривать AnythingLLM Docker как кандидат на начальный интерфейс, подтвердить пригодность прототипом.
4. Реализовать собственный слой оркестрации и интеграции инструментов; не делать Hermes или Bionic обязательной runtime-зависимостью до сравнительных испытаний.
5. Реализовать собственную модель постоянной памяти, используя идеи Hermes Agent: память пользователя, проекта, диалогов и навыков.
6. Развивать обработку инженерных документов на основе проверенных наработок Project Expert AI.
7. С самого начала моделировать владельца и область доступа у данных, даже если фактически используется один пользователь.

## Последствия

- Можно заменить UI или LLM runtime без переписывания доменной логики.
- Требуется собственный API и адаптеры интеграции.
- Нужно отдельно проверить, как AnythingLLM передаёт контекст и источники в наш backend.
- Необходимо измерять качество локальных моделей на реальных тестовых документах до выбора конкретных моделей.
- Выбор БД, vector store и graph store остаётся открытым до сравнительного прототипа.
