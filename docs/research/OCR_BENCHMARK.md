# OCR Benchmark: методика и запуск

## Назначение

Benchmark измеряет качество OCR на воспроизводимом наборе изображений с human-verified Ground Truth. Изображения обрабатываются локально; сетевые OCR API не используются.

Текущий этап предоставляет:
- общий протокол OCREngine, чтобы сравнивать движки без изменения метрик;
- готовый адаптер Tesseract;
- CER и WER;
- опциональную оценку локализации текста по IoU, Precision и Recall;
- время обработки и снимки RSS памяти при установленном psutil;
- JSON-отчёт с ошибками и версиями движков.

Это инфраструктура для benchmark, а не утверждение, что Tesseract уже признан лучшим движком. PaddleOCR и EasyOCR остаются кандидатами для следующих адаптеров; их зависимости и API не добавляются в production runtime до отдельной проверки совместимости и benchmark.

## Установка

1. Установить Tesseract OCR и необходимые языковые данные (как минимум rus и eng).
2. Установить проект с extras:

    pip install -e ".[ocr,benchmark]"

Проверить доступность Tesseract:

    tesseract --version
    tesseract --list-langs

## Формат набора

Создать каталог benchmark, например benchmarks/ocr/sample/, и положить туда изображения страниц. Рядом создать manifest.json:

    {
      "cases": [
        {
          "id": "specification-page-001",
          "image": "page-001.png",
          "ground_truth": "СП 30.13330.2020 Внутренний водопровод и канализация зданий",
          "ground_truth_words": [
            {"text": "СП", "bbox": [90, 70, 150, 125]},
            {"text": "30.13330.2020", "bbox": [165, 70, 520, 125]}
          ]
        }
      ]
    }

ground_truth должен быть вручную проверен человеком. ground_truth_words необязателен; если указан, координаты должны быть в пикселях исходного изображения и соответствовать отдельным словам.

Набор должен содержать разные классы страниц:
- нативный PDF-текст и сканированные страницы;
- русский, английский и смешанный текст;
- номера пунктов, обозначения СП/ГОСТ, числа, единицы измерения;
- мелкий текст, штампы, повороты, низкий контраст и шум;
- таблицы, выноски и фрагменты чертежей.

Не помещать конфиденциальные проектные документы в публичный репозиторий или публичный CI. Для локального benchmark можно использовать обезличенные страницы; в репозитории хранить только методику и синтетические/разрешённые fixtures.

## Запуск

    personal-expert-ai-ocr-benchmark --manifest benchmarks/ocr/sample/manifest.json --output artifacts/ocr-benchmark-tesseract.json --language rus+eng --config "--psm 3"

Альтернативный запуск:

    python -m app.processing.ocr_benchmark --manifest <manifest.json> --output <report.json>

Скрипт проверяет, что пути изображений остаются внутри каталога manifest. Ошибка одного engine/case записывается в отчёт и не скрывается.

## Метрики

- CER (Character Error Rate): расстояние редактирования на уровне символов / число символов эталона.
- WER (Word Error Rate): расстояние редактирования на уровне слов / число слов эталона.
- Precision / Recall: доля правильно локализованных слов среди распознанных / эталонных слов.
- IoU: пересечение bounding boxes, делённое на объединение; совпадением считается IoU не ниже 0.5 и одинаковый нормализованный токен.
- Latency: время распознавания одного изображения в миллисекундах.
- RSS delta: разница двух снимков resident set size до и после обработки. Это не peak RAM; для точного пикового измерения потребуется отдельный sampler.

Сравнивать движки следует на одинаковых изображениях, языках, DPI и preprocessing. Отчёт должен сохранять версии библиотек, движков и языковых моделей.

## Ограничения текущей версии

- CLI включает Tesseract adapter; OCREngine позволяет подключить другие реализации к тому же runner.
- PaddleOCR и EasyOCR ещё не интегрированы и не сравнивались.
- CI проверяет метрики и контракт runner на fixtures; это не заменяет оценку на реальных инженерных сканах.
- CER/WER не оценивают понимание таблиц, формул, схем и инженерного смысла.
- Геометрическая дедупликация в PDF pipeline использует совпадение токена и перекрытие локальных native/OCR boxes; её качество также нужно оценить на размеченных реальных страницах.

## Критерий выбора production OCR

Не выбирать движок только по одному среднему CER. Сравнивать CER/WER по классам страниц, precision/recall локализации, скорость, RSS/пиковую память, поддержку русского языка, стабильность координат, лицензию, сложность установки и воспроизводимость. Решение фиксировать отдельным ADR.
