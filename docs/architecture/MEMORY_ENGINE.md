# Memory Engine — память и Skills

- Статус: базовая архитектурная спецификация, версия 1.0
- Дата: 2026-11-01

## 1. Назначение и границы

Memory Engine сохраняет полезный контекст между сессиями. Он не заменяет проектные документы, Knowledge Model или нормативную базу и не является самостоятельным источником инженерной истины. Skills Registry хранит версионируемые процедуры с ограниченными правами.

## 2. Области памяти

- **User memory** — подтверждённые предпочтения и настройки пользователя.
- **Tenant memory** — общие правила организации.
- **Project memory** — решения, ограничения, контекст и вопросы конкретного проекта.
- **Conversation/session memory** — краткосрочный контекст и ссылки на прошлые сессии.
- **Task memory** — состояние длительной задачи и checkpoints.

Каждая запись имеет одну основную область действия, владельца, ACL, происхождение и срок хранения. Области не смешиваются автоматически.

## 3. Типы записей

Preference, ProjectDecision, Constraint, OpenQuestion, ContextSummary, ProcedureNote, SessionReference. Не следует сохранять каждое сообщение. Сначала формируется кандидат, проверяется полезность, конфликт, чувствительность и scope.

## 4. Жизненный цикл MemoryEntry

Состояния: proposed → confirmed/rejected → superseded/expired → deleted.

LLM может предложить запись, но не подтверждать её от имени пользователя. Предпочтения и проектные решения требуют подтверждения либо явного действия пользователя. Запись хранит даты, valid_from/to, source_refs, автора, reviewer и причину изменения. Исправление создаёт новую ревизию/событие. Удалённая запись исключается из retrieval и производных индексов по retention policy.

## 5. Поиск по памяти

Поиск выполняется отдельно от поиска по проектным документам. Сначала проверяются scope и права, затем применяются метаданные, полнотекстовый и при необходимости семантический поиск. Память добавляется в контекст модели только при релевантности.

Память всегда маркируется как память, а не первоисточник. Если она противоречит актуальному проектному документу, документ имеет приоритет для утверждений о содержимом проекта; конфликт показывается пользователю.

## 6. Поиск по сессиям

Индексируются разрешённые сообщения, summaries и метаданные. Результат содержит ссылку на исходную сессию и сообщение. Учитываются ACL и retention. SQLite FTS5 или PostgreSQL FTS — варианты реализации для прототипа; глобальный индекс без scope filter запрещён.

## 7. Skills Registry

Skill — декларативная версия процедуры. Минимальные поля:
- id, name, description, version;
- owner/scope и ACL;
- input/output schema;
- instructions и policy;
- allowed tools и required permissions;
- model capability requirements;
- timeout, resource limits, retry policy;
- validation rules, acceptance criteria и tests;
- changelog, status, checksum.

Опубликованная версия неизменяема; изменение создаёт новую версию. Исполнение фиксирует точный skill_version_id.

## 8. Типы Skills

- Document Skills: извлечение реквизитов, классификация, сравнение редакций.
- Retrieval Skills: поиск определённых сведений и сбор доказательств.
- Engineering Skills: проверки требований по дисциплинам.
- Reporting Skills: формирование структурированного результата.
- Administration Skills: ограниченные операции обслуживания.

Engineering Skill не подменяет нормативный движок произвольной инструкцией LLM. Проверяемые вычисления и правила реализуются детерминированным кодом, где это возможно; LLM используется для интерпретации и объяснения.

## 9. Выполнение Skill

1. Проверить пользователя, tenant/project scope и разрешения.
2. Валидировать входную схему.
3. Загрузить неизменяемую версию Skill.
4. Сформировать минимальный контекст с доказательствами.
5. Проверить allowlist инструментов.
6. Выполнить шаги с timeout и resource limits.
7. Проверить output schema и citations.
8. Сохранить SkillExecution, manifest и аудит.
9. Показать результат и ограничения.

LLM не может расширять allowlist, менять scope, читать произвольные файлы или инициировать внешние соединения.

## 10. Инструменты и MCP

Инструменты вызываются через backend Tool Gateway. Для каждого инструмента заданы schema, права, режим read/write/network, scope и аудит. Внешние MCP и web search по умолчанию выключены. Local-only режим разрешает только локальные endpoints из явного allowlist. Изменяющие действия требуют подтверждения, если затрагивают проектные данные, память, права или файлы.

## 11. Приватность

Пользователь может просмотреть, исправить и удалить доступные ему записи. Определяются экспорт, retention, очистка индексов и поведение резервных копий. Секреты, пароли и токены не сохраняются в памяти. Память одного проекта не переносится в другой без явного разрешения.

## 12. Hermes Agent как источник идей

Изучаемые паттерны: компактная пользовательская память, отдельные project/session контексты, полнотекстовый поиск сессий, Skills on-demand и делегирование ограниченных задач. Это архитектурные идеи, а не обязательная runtime-зависимость. Владение данными и ACL остаются в Personal Expert AI.
